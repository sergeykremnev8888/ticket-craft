# API Gateway

Единая точка входа в HTTP API Ticket Craft. Направляет запросы в Catalog Service и Order Service, проверяет JWT и защищает сервисы от перегрузки.

[← Обзор проекта и быстрый старт](../README.md)

## Роль в архитектуре

Gateway принимает клиентские запросы и передаёт их бизнес-сервисам:
- просмотр мероприятий и билетов — в Catalog Service;
- создание и просмотр заказов — в Order Service.

Для проверки JWT используются ключи Keycloak.
Redis хранит состояние ограничителей частоты запросов.

Бизнес-правила покупки, проверка scopes и принадлежности заказа пользователю выполняются в соответствующих сервисах.

## Технологии

Java 21, Spring Boot, Spring Cloud Gateway / WebFlux, Spring Security, Redis, Resilience4j, Actuator, Micrometer и OpenTelemetry.

## Основные возможности

- Маршрутизация клиентских запросов.
- Проверка подписи JWT, срока действия, issuer и audience.
- Rate limiting по IP для каталога и по JWT subject для заказов.
- Ограничение параллельных запросов отдельно для каждого маршрута.
- Ограничение размера тела и времени его чтения.
- Circuit Breaker и таймауты обращений к бизнес-сервисам.
- Ограниченный пул HTTP-соединений к downstream-сервисам.
- Настройка CORS.
- Передача correlation ID и ответы об ошибках в формате Problem Detail.
- Удаление недоверенных входящих `Forwarded` / `X-Forwarded-*`.
- Метрики, распределённая трассировка, liveness/readiness.
- Graceful shutdown с ожиданием активных запросов в пределах таймаута.

## Защита от перегрузки

Основные значения по умолчанию:

| Механизм | Значение |
|---|---|
| Rate limiting каталога | 10 токенов/с, ёмкость 20, ключ — IP |
| Rate limiting заказов | 5 токенов/с, ёмкость 10, ключ — пользователь |
| Параллельные запросы | Catalog — 64, Order — 32 на экземпляр Gateway |
| Размер тела запроса | До 64 KB |
| Время чтения тела | До 5 с |
| HTTP-соединения | До 64 на downstream-адрес |
| Ожидание свободного соединения | До 500 мс |

Каждый запрос расходует один токен.
При недоступности Redis rate limiting работает в режиме fail-open:
запросы пропускаются, деградация отражается в логах и метриках.
Локальные ограничения параллельной обработки продолжают действовать.

Превышение частоты возвращает `429`, параллельности — `503`,
размера тела — `413`, времени чтения тела — `408`.

## API и проверка

HTTP-порт — `8080`.

| Метод | Путь | Назначение | Авторизация |
|---|---|---|---|
| `GET` | `/api/v1/catalog/events` | Список мероприятий | Не требуется |
| `GET` | `/api/v1/catalog/events/{eventId}` | Мероприятие и билеты | Не требуется |
| `POST` | `/api/v1/orders` | Создание заказа | JWT |
| `GET` | `/api/v1/orders/{orderId}` | Просмотр своего заказа | JWT |

Для создания заказа требуется `Idempotency-Key`.
Идемпотентность реализована в Order Service.

Проверка состояния и готовности Gateway:

```powershell
curl.exe -i http://localhost:8080/actuator/health/liveness
curl.exe -i http://localhost:8080/actuator/health/readiness
```

Ожидаемый результат — `200 OK` и `{"status":"UP"}`.

Эти проверки отражают состояние самого приложения.
Доступность Redis и бизнес-сервисов в состав probes не включена.

Проверка маршрута каталога:

```powershell
curl.exe -i http://localhost:8080/api/v1/catalog/events
```

Настройка авторизации в Postman и полный сценарий покупки описаны
в [корневом README](../README.md#проверка-работоспособности).

Маршруты `/fallback/**` используются внутри Gateway.
Прямые клиентские обращения к ним возвращают `404`.

## Метрики и трассировка

В Docker-окружении метрики доступны по адресу:

http://localhost:8080/actuator/prometheus

В профилях `docker` и `local` endpoint открыт для демонстрационного
окружения. В базовой конфигурации и профиле `prod` требуется JWT
со scope `metrics.read`.

Публикуются метрики HTTP-запросов, пула соединений и деградации
rate limiter. Трассировки отправляются в Jaeger через OTLP.

## Запуск

Команды выполняются из корня репозитория.

Перед первым запуском подготовьте `.env` по
[инструкции](../README.md#быстрый-старт).

Запуск всего проекта:

```powershell
docker compose up -d --build
```

Просмотр состояния и логов:

```powershell
docker compose ps api-gateway
docker compose logs --tail 100 api-gateway
```

Остановка Gateway:

```powershell
docker compose stop api-gateway
```

При остановке Gateway ожидает завершения активных запросов.
Таймаут фазы завершения Spring — 30 с, время ожидания Docker — 45 с.
Обычные таймауты запросов при этом продолжают действовать.

Основные переменные окружения:

- Маршруты: `GATEWAY_CATALOG_URI`, `GATEWAY_ORDER_URI`.
- Redis: `REDIS_URL`.
- JWT: `JWT_ISSUER_URI`, `JWT_JWK_SET_URI`, `JWT_AUDIENCE`.
- Параллельность: `GATEWAY_CATALOG_MAX_CONCURRENT`,
  `GATEWAY_ORDER_MAX_CONCURRENT`.
- Тело запроса: `GATEWAY_MAX_BODY_SIZE`, `GATEWAY_BODY_READ_TIMEOUT`.
- HTTP-пул: `GATEWAY_HTTP_POOL_MAX_CONNECTIONS`,
  `GATEWAY_HTTP_POOL_ACQUIRE_TIMEOUT_MS`.
- Трассировка: `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`,
  `TRACING_SAMPLING_PROBABILITY`.

При запуске через Docker Compose переменные должны быть переданы
в `environment` контейнера. Само наличие переменной в `.env`
не передаёт её приложению автоматически.

Пример окружения — [`.env.example`](../.env.example).

## Тесты

Нужны JDK 21 и работающий Docker для Testcontainers.
Поднимать окружение через Docker Compose перед тестами не требуется.

```powershell
.\mvnw.cmd -pl api-gateway -am test
```

Тесты проверяют безопасность, обработку ошибок, rate limiting,
ограничения тела и параллельности, исчерпание HTTP-пула,
health probes и защиту от подмены forwarded-заголовков.

В тестовом профиле `test` экспорт трассировок отключён.

## Ограничения

- Gateway не управляет бизнес-транзакциями и идемпотентностью заказов.
- Текущая конфигурация рассчитана на прямое подключение клиента.
  При размещении за reverse proxy необходимо отдельно настроить
  доверие к прокси и определение исходного IP.
- В Docker-сети адрес подключения может соответствовать сетевому шлюзу,
  поэтому разные клиенты могут разделять один IP-лимит.
- Параллельность ограничивается отдельно на каждом экземпляре Gateway;
  rate limiting использует общее состояние в Redis.
- Наличие профиля `prod` не заменяет настройку TLS, сетевого доступа,
  секретов и эксплуатационного мониторинга.
