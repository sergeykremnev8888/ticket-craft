# Notification Service

Внутренний сервис уведомлений Ticket Craft.
Обрабатывает подтверждённые заказы и имитирует отправку уведомления
записью в лог.

[← Обзор проекта и быстрый старт](../README.md)

## Роль в архитектуре

Сервис получает информацию о подтверждённых заказах через Kafka.
Его обработка не является условием завершения покупки.

Собственная PostgreSQL-база используется для учёта обработанных сообщений
и защиты от повторной обработки.

## Технологии

Java 21, Spring Boot, Spring Kafka, Spring JDBC,
PostgreSQL, Flyway, Actuator, Micrometer и OpenTelemetry.

## Основные возможности

- Асинхронная обработка подтверждённых заказов.
- Дедупликация сообщений с сохранением результата в PostgreSQL.
- Повторная обработка временных ошибок.
- Dead Letter Queue для проблемных сообщений.
- Метрики и распределённая трассировка.

## API и проверка

HTTP-порт — `8083`.

Клиентского бизнес REST API нет.
HTTP-сервер используется для Actuator.

Проверка готовности:

```powershell
curl.exe -i http://localhost:8083/actuator/health
```

После успешной покупки проверьте логи:

```powershell
docker compose logs --tail 100 notification-service
```

Ожидается запись об обработке подтверждённого заказа.

Полный сценарий покупки описан в
[корневом README](../README.md#проверка-работоспособности).

## Запуск

Запуск всего проекта:

```powershell
docker compose up -d --build
```

Перед первым запуском подготовьте `.env` по
[инструкции](../README.md#быстрый-старт).

Flyway автоматически создаёт необходимые таблицы.

Просмотр состояния и логов:

```powershell
docker compose ps notification-service
docker compose logs --tail 100 notification-service
```

Параметры подключения к PostgreSQL и Kafka приведены
в [`.env.example`](../.env.example) и Docker Compose.

## Тесты

Нужны JDK 21 и работающий Docker.

```powershell
.\mvnw.cmd -pl notification-service -am test
```

Тесты проверяют дедупликацию, конкурентную обработку,
откат транзакции при ошибке, retry и Dead Letter Queue.

## Ограничения

- Отправка email, SMS и push не реализована.
- Запись в лог не откатывается вместе с транзакцией БД,
  поэтому при сбоях возможны повторные строки.
- Подключение реального провайдера потребует отдельного решения
  для надёжной доставки и идемпотентности внешних вызовов.
